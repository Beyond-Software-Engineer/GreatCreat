**学管平台软件系统**

**软件需求规格说明书**


# 引言

## 文档目的

本文档对计算机科学技术学院数据中台系统的软件开发需求做了全面的分析，明确所要开发的软件应具有的功能、性能及界面设计要求。使系统分析人员及软件开发人员能够清晰地了解用户需求，掌握该系统的使用场景、核心功能、性能指标，并在此基础上进一步提出概要设计说明书和完成后续的设计与开发工作。

本文档预期读者为项目经理、产品设计人员、软件设计人员、开发人员、测试人员、运维人员及学院相关管理工作人员。开发人员阅读本需求规格说明书，需要特别注意功能需求中的具体描述和对软件设计过程中数据统计、权限控制、实时展示等潜在出错地方的相关处理。

## 项目背景

本项目需求基于计算机学院日常运营管理的实际痛点提出，学院在开展日常数据统计、工程认证等工作时，需向各部门、教师多方收集科研、教学、学生管理等相关数据，数据获取流程繁琐、效率低下，且缺乏统一的数据管理与展示载体。为解决上述问题，开发**计算机科学技术学院数据中心管理系统**，本系统仅服务于计算机学院内部，不覆盖学校其他学院，旨在打造学院级数据中心，整合教学、科研、学生管理、学院日常运行全维度数据，实现数据的统一录入、存储、统计、展示与管理。

## 术语定义

**数据中心管理系统**：本系统中指仅服务计算机学院的内部数据中心，实现学院各类数据的统一整合、管理、统计与可视化展示的软件系统。

**横向项目**：指学院与企业、其他单位合作的非财政拨款科研项目。

**EI/SCI 检索**：指论文被工程索引（EI）、科学引文索引（SCI）数据库收录的认定标准。

**A/B/C 区论文**：指按照学校 / 学院学术评价标准，对期刊、会议论文划分的学术等级。

**数据大屏**：指系统中以可视化图表、数字看板等形式，实时展示学院核心数据指标的专属页面。

**课时量**：指教师在一个学期内完成的教学课程时长，是学校对教师教学工作的核心考核指标。

# 业务流程描述

本系统的核心业务流程围绕**数据全生命周期管理**展开，覆盖从数据录入到最终展示、使用的全部环节，各角色按权限参与对应流程，核心业务流程如下：

1.  **数据录入**：教师、各办公室人员按系统分配权限，分别录入科研、教学、学生管理等相关原始数据，录入时需按系统要求填写必填字段，保证数据规范性；
2.  **数据审核**：管理员对各角色录入的原始数据进行审核，审核通过后数据正式存入系统数据库；审核不通过的数据退回至录入人，并标注修改原因；
3.  **数据处理**：系统对审核通过的数据进行自动计算、分类、统计，如课时量汇总、论文分区统计、学生学分核算等；
4.  **数据展示**：系统将处理后的数据通过数据可视化大屏、模块查询页面等形式进行展示，供各角色按权限查看；
5.  **数据使用**：各角色可按权限对数据进行查询、核对、导出、打印等操作，支撑学院日常管理、工程认证、数据上报等工作。

本流程支持数据的实时更新与二次录入，当原始数据发生变动时，录入人可发起修改申请，经管理员审核后，系统同步更新数据并重新完成统计计算。

# 任务概述

## 目标

1.  搭建仅服务于计算机学院的学院级数据中台，实现教学、科研、学生管理、学院日常运行全维度数据的统一整合与管理，解决数据分散、收集困难的痛点。
2.  实现多角色分级权限控制，为教师、管理员、各办公室人员分配不同的操作与查看权限，保证数据管理的安全性与规范性。
3.  完成科研、教学、学生管理三大核心板块的数据录入、统计、查询功能，支撑学院日常数据统计与工程认证等专项工作。
4.  开发数据可视化大屏，实现学院核心数据指标的实时展示，为学院领导决策提供数据支撑。
5.  实现数据的核对、导出、打印等基础操作，满足学院日常办公的数据使用需求。
6.  保证系统的可扩展性与适应性，支持后续业务需求的补充与功能模块的扩展。

## 运行环境

### **软件运行环境**

1.  操作系统：Windows（客户端 / 管理端）
2.  浏览器：主流浏览器（Chrome、Edge、Firefox，版本为最新稳定版）
3.  数据库：MySQL（8.0 及以上版本）
4.  前端框架：Vue3 及以上
5.  后端框架：Spring Boot 及以上

## 功能划分

本系统按业务模块划分为六大核心功能模块，各模块相互协同，实现数据的全生命周期管理，具体功能划分如下：

1.  系统信息管理：负责系统基础架构与权限管理，包含组织架构、人员管理、角色管理、权限管理、日志管理等子功能；
2.  科研数据管理：负责学院科研相关数据的管理，包含科研数据录入、统计、查询等子功能；
3.  教学数据管理：负责学院教学相关数据的管理，包含开课信息管理、课时量统计、培养方案管理等子功能；
4.  学生管理数据：负责学院学生相关数据的管理，包含学生信息管理、学业数据管理、生源数据管理等子功能；
5.  数据可视化大屏：负责学院核心数据的实时可视化展示，包含领导视角专属大屏、多维度数据看板等子功能；
6.  基础数据操作管理：负责系统通用数据操作，包含数据核对、导出、打印、批量导入等子功能。

## 功能描述

### **系统信息管理**

此模块用于系统的基础信息与权限体系管理，是系统正常运行的基础，包含组织架构、人员管理、角色管理、权限管理、日志管理五个子功能，核心实现多角色分级权限控制，保证数据操作与查看的安全性。

#### 组织架构

1.  用于创建和存储计算机学院内部的组织结构层级和基本信息，贴合学院实际部门设置；
2.  可对部门信息进行增删改查操作，可对部门的层级关系进行维护（如新增教研室、调整办公室归属等）；
3.  添加部门时需要填写的信息有：部门名称、部门编码、部门描述、是否是父级，其中部门名称、部门编码为必填项，部门编码具有唯一性，不可重复；
4.  支持部门信息的批量导入与修改，支持部门结构的树形图展示。

#### 人员管理

1.  用于创建和存储学院内系统使用者的个人信息，关联学院实际人员编制；
2.  可对人员信息进行增删改查操作，可将人员分配至对应部门，支持人员与部门的解绑与重新分配；
3.  添加人员时需要填写的信息有：姓名、工号/学号、性别、所属部门、联系电话、账号状态，其中姓名、工号/学号为必填项，工号/学号为系统登录账号，具有唯一性；
4.  支持人员信息的批量导入，支持按部门、姓名、工号/学号进行模糊查询。

#### 角色管理

1.  用于创建和管理系统的角色类型，贴合学院实际使用场景，预设角色为：教师、管理员、各办公室人员（科研办、教学办、学工办）；
2.  可对角色信息进行增删改查操作，支持自定义新增角色（如学院领导、教研组长等）；
3.  添加角色时需要填写的信息有：角色名称、角色编码、角色描述，其中角色名称、角色编码为必填项，角色编码具有唯一性；
4.  支持角色的批量管理，支持按角色名称进行模糊查询。

#### 权限管理

1.用于为不同角色分配系统操作与数据查看权限，实现分级权限控制，权限细分为：数据录入、数据审核、数据查询、数据修改、数据导出、大屏查看、系统管理等；

2.可对角色权限进行增删改查操作，支持为单个角色分配多项权限，支持批量为多个角色分配相同权限；

3.权限分配结果实时生效，当角色权限发生变动时，对应账号的系统操作权限同步更新；

4.支持权限的一键重置与恢复，支持按角色、权限类型进行查询。

**3.4.1.5 日志管理**

1.用于记录系统内所有用户的操作行为，实现操作行为的可追溯，日志内容包含：操作用户、操作时间、操作模块、操作内容、操作结果、登录IP；

2.支持按操作用户、操作时间、操作模块、操作结果进行多条件组合查询，支持日志内容的模糊查询；

3.支持日志的分页展示，支持日志的导出与打印，日志数据永久保存，不支持手动删除。

**3.4.2 科研数据管理**

此模块用于学院科研相关数据的全流程管理，是系统的核心业务模块之一，贴合学院科研工作实际，包含科研数据录入、科研数据统计、科研数据查询三个子功能，核心实现科研数据的统一管理与精准统计。

**3.4.2.1 科研数据录入**

1\. 录入角色为：教师、科研办人员，管理员可进行补录；教师仅可录入本人科研数据，科研办人员可录入全院科研数据；

2\. 可录入的科研数据类型包含：论文、科研项目、横向项目经费，各类型数据需填写对应必填字段：

论文：论文标题、作者、发表期刊/会议、收录类型（EI/SCI/其他）、论文分区（A/B/C/无）、发表时间，其中论文标题、作者、发表时间为必填项；

科研项目：项目名称、项目负责人、项目类型（纵向/横向）、获批时间、经费金额、到账状态，其中项目名称、项目负责人、获批时间、经费金额为必填项；

横向项目经费：经费项目名称、负责人、到账金额、到账时间、付款单位，其中经费项目名称、负责人、到账金额、到账时间为必填项；

1.  支持单条数据录入与批量导入，支持上传相关附件（如论文录用通知、项目立项通知书、经费到账凭证）
2.  录入的数据需提交管理员审核，审核通过后正式存入系统，审核不通过的数据可退回修改后重新提交。

**3.4.2.2 科研数据统计**

1.  统计角色为：管理员、科研办人员、学院领导，教师仅可统计本人科研数据；
2.  系统支持自动实时统计，统计维度包含：时间维度（按年/月/季度）、人员维度（按个人/部门/全院）、数据类型维度（论文/项目/经费）；
3.  核心统计指标包含：获批项目数量、项目总经费金额、经费到账金额、论文发表总数、EI/SCI检索论文数量、A/B/C区论文数量；
4.  支持统计结果的二次筛选与排序，支持按多个维度组合统计，统计结果以表格、柱状图、折线图等形式展示。

**3.4.2.3 科研数据查询**

1.  查询角色按权限分配，教师可查询本人科研数据，各部门人员可查询本部门相关科研数据，管理员、学院领导可查询全院科研数据；
2.  支持按多条件组合查询，查询条件包含：时间、人员、部门、论文收录类型、论文分区、项目类型、经费到账状态等；
3.  支持模糊查询与精准查询，支持查询结果的分页展示、导出与打印；
4.  支持查看数据的详细信息与附件，支持对未审核数据的修改与撤回。

**3.4.3 教学数据管理**

此模块用于学院教学相关数据的全流程管理，是系统的核心业务模块之一，贴合学院教学工作实际，包含开课信息管理、课时量统计、培养方案管理、教学数据查询四个子功能，核心实现教学数据的统一管理与课时量考核。

**3.4.3.1 开课信息管理**

1.  录入角色为：教学办人员、教师，管理员可进行补录；教师仅可录入本人授课信息，教学办人员可录入全院开课信息；
2.  录入的开课信息包含：学期、课程名称、课程编码、授课教师、授课专业、授课班级、课时数、课程类型，其中学期、课程名称、授课教师、课时数为必填项，课程编码具有唯一性；
3.  支持单条开课信息录入与批量导入，支持对开课信息的修改与删除，修改后需提交管理员审核；
4.  支持按学期、专业、班级展示开课计划，支持开课信息的批量导出。

**3.4.3.2 课时量统计**

1.  统计角色为：管理员、教学办人员、学院领导，教师仅可统计本人课时量；
2.  系统支持自动实时统计，统计维度包含：时间维度（按学期/学年）、人员维度（按个人/部门/全院）、专业维度（按专业/班级）；
3.  核心统计指标包含：全院开课总数、各专业开课数、教师个人课时量、各部门教师平均课时量、全院教师平均课时量；
4.  支持与学校下达的教学课时任务进行对比，自动标注未完成课时任务的教师与部门，支持统计结果的可视化展示。

**3.4.3.3 培养方案管理**

1.  管理角色为：教学办人员、管理员，支持全院各专业培养方案的录入、修改、查询与保存；
2.  录入的培养方案信息包含：专业名称、学制、培养目标、核心课程、课程学分、学分要求、毕业条件，其中专业名称、核心课程、课程学分为必填项；
3.  支持按专业、学制查询培养方案，支持培养方案的版本管理，支持新增培养方案版本并保留历史版本；
4.  支持培养方案的导出与打印，支持核心课程与学分的单独统计。

**3.4.3.4 教学数据查询**

1.  查询角色按权限分配，教师可查询本人授课与课时量数据，教学办人员可查询全院教学数据，管理员、学院领导可查询所有教学相关数据；
2.  支持按多条件组合查询，查询条件包含：学期、课程名称、授课教师、专业、班级、课时数等；
3.  支持模糊查询与精准查询，支持查询结果的分页展示、导出与打印；
4.  支持查看课时量统计的详细明细，支持对未审核开课信息的修改与撤回。

**3.4.4 学生管理数据**

此模块用于学院学生相关数据的全流程管理，是系统的核心业务模块之一，贴合学院学生管理工作实际，包含学生信息管理、学业数据管理、生源数据管理、学生数据查询四个子功能，核心实现学生数据的统一管理与学业进度监控。

**3.4.4.1 学生信息管理**

1.  录入角色为：学工办人员、辅导员，管理员可进行补录；
2.  录入的学生信息包含：学号、姓名、性别、所属专业、所属班级、入学年份、生源城市、毕业中学、入学分数、联系方式、学籍状态，其中学号、姓名、所属专业、所属班级、入学年份为必填项，学号具有唯一性；
3.  支持学生信息的批量导入与修改，支持学籍状态的更新（如休学、复学、毕业）；
4.  支持按专业、班级、入学年份展示学生信息，支持学生信息的批量导出。

**3.4.4.2 学业数据管理**

1.  录入角色为：教学办人员、辅导员，管理员可进行补录；
2.  录入的学生学业数据包含：学号、姓名、学期、修读课程、课程成绩、获得学分、总学分、专业排名，其中学号、姓名、修读课程、获得学分为必填项；
3.  系统支持自动核算学生总学分与学习进度，对比对应专业培养方案的学分要求，自动标注学业进度未达预期的学生；
4.  支持按学期、专业、班级统计学生的平均成绩、学分获取率、专业排名分布，支持对学业预警学生的标注与跟踪。

**3.4.4.3 生源数据管理**

1.  统计角色为：学工办人员、管理员、学院领导，核心实现学生生源数据的分类统计；
2.  系统支持自动实时统计，统计维度包含：生源城市、生源省份、毕业中学、入学分数段；
3.  核心统计指标包含：各城市/省份生源人数、各毕业中学生源人数、入学分数段人数分布、平均入学分数；
4.  支持生源数据的可视化展示，支持按年份对比生源数据变化。

**3.4.4.4 学生数据查询**

1.  查询角色按权限分配，辅导员可查询所带班级学生数据，学工办/教学办人员可查询全院学生数据，管理员、学院领导可查询所有学生相关数据；
2.  支持按多条件组合查询，查询条件包含：学号、姓名、专业、班级、入学年份、生源城市、学业进度、专业排名等；
3.  支持模糊查询与精准查询，支持查询结果的分页展示、导出与打印；
4.  支持查看学生的详细学业信息与生源信息，支持对学生数据的修改与审核。

### **3.4.5 数据可视化大屏**

此模块是系统的核心展示模块，为学院领导与管理人员提供实时、直观的核心数据看板，仅对管理员、学院领导、各部门负责人开放查看权限，支持大屏数据的实时刷新与多维度切换。

**3.4.5.1 领导视角专属大屏**

1.  为学院领导打造专属可视化大屏，整合科研、教学、学生管理三大板块的核心数据指标，实现一屏看全院；
2.  大屏布局按数据重要性划分，核心展示区域为：实时科研经费到账金额、获批项目数量、论文发表统计、全院平均课时量、学生学分获取率、学业预警学生数；
3.  所有数据实时更新，更新频率为5分钟/次，支持手动触发实时刷新；
4.  大屏支持全屏展示，适配会议室、办公室等不同使用场景的显示设备。

**3.4.5.2 科研数据看板**

1.  单独展示科研板块的核心数据，以数字看板+可视化图表的形式呈现；
2.  数字看板展示：年度获批项目数、年度经费到账总额、EI/SCI论文数、A区论文数等核心指标；
3.  可视化图表展示：论文收录类型分布、论文分区分布、项目经费到账趋势、各部门科研成果排名；
4.  支持按年/月切换数据时间维度，支持查看数据明细。

**3.4.5.3 教学数据看板**

1.  单独展示教学板块的核心数据，以数字看板+可视化图表的形式呈现；
2.  数字看板展示：本学期开课总数、全院教师平均课时量、各专业开课数、未完成课时任务教师数等核心指标；
3.  可视化图表展示：各部门课时量分布、各专业开课数对比、教师课时量排名、学期开课趋势；
4.  支持按学期/学年切换数据时间维度，支持查看数据明细。

**3.4.5.4 学生管理数据看板**

1.  单独展示学生管理板块的核心数据，以数字看板+可视化图表的形式呈现；
2.  数字看板展示：全院学生总数、各专业学生数、学业进度达标率、学业预警学生数、各省份生源人数等核心指标；
3.  可视化图表展示：生源城市分布、入学分数段分布、专业排名分布、学生学分获取率趋势；
4.  支持按入学年份/学期切换数据时间维度，支持查看数据明细。

**3.4.6 基础数据操作管理**

此模块是系统的通用功能模块，为所有角色提供数据的基础操作功能，包含数据核对、数据导出、数据打印、批量数据导入四个子功能，核心满足学院日常办公的数据使用需求。

**3.4.6.1 数据核对**

1.  所有角色均可按权限对已审核的数据进行核对，支持单条数据核对与批量数据核对；
2.  核对时可对比原始录入数据与系统统计数据，支持标注核对结果（核对无误/数据错误）；
3.  若发现数据错误，可发起修改申请，填写修改原因并提交管理员审核，审核通过后系统同步更新数据；
4.  支持核对记录的查询与保存，核对记录包含：核对人、核对时间、核对数据、核对结果。

**3.4.6.2 数据导出**

1.  所有角色均可按权限对查询结果与统计结果进行导出，支持多种导出格式：Excel、CSV、PDF；
2.  支持单条数据导出、批量数据导出与全量数据导出，支持导出数据的字段自定义选择；
3.  导出数据时自动生成导出时间与导出人信息，导出文件支持直接保存至本地；
4.  支持批量导出任务的后台运行，避免大数量级数据导出时的系统卡顿。

**3.4.6.3 数据打印**

1.  所有角色均可按权限对查询结果、统计结果、数据明细进行打印，支持打印格式的自定义设置（纸张大小、边距、字体、页码）；
2.  支持单页打印、批量打印与预览打印，打印前可对打印内容进行编辑与筛选；
3.  支持打印记录的查询，打印记录包含：打印人、打印时间、打印内容、打印页数。

**3.4.6.4 批量数据导入**

1.  所有具有数据录入权限的角色均可进行批量数据导入，支持导入的文件格式为：Excel、CSV；
2.  系统提供标准的导入模板，导入前需按模板规范填写数据，支持模板的下载；
3.  导入时系统自动校验数据格式与必填字段，对错误数据进行标注并提示错误原因，支持正确数据的单独导入与错误数据的修改后重新导入；
4.  支持批量导入结果的查看，导入结果包含：导入总数、成功数、失败数、错误明细。

**4 适应性**

1.  系统在操作方式、运行环境、与其他软件的接口发生变化时，应具备良好的适应能力，支持主流浏览器的版本更新，支持数据库的常规版本升级；
2.  系统的所有参数设置均为可配置化，如角色权限、数据统计维度、大屏展示指标、数据更新频率等，不可将参数直接写在代码里，支持管理员在系统后台进行灵活配置；
3.  系统适配学院教职工的使用习惯，操作界面简洁易懂，避免复杂的操作流程，支持快捷键操作与常用功能的收藏；
4.  系统具备良好的业务可扩展性，支持后续新增数据统计项、功能模块与角色类型，无需对核心代码进行大规模修改；
5.  系统支持与学院现有办公软件的适配，如Excel、WPS等，保证数据导入导出的兼容性。

**5 运行需求**

**5.1 用户界面**

1.  界面整体布局合理，按功能模块进行分区，各模块之间的切换流畅，操作路径简洁，避免多层级嵌套；
2.  界面图标设计贴合功能含义，简洁直观，易识别，支持图标hover提示，对核心功能与常用功能进行醒目标注；
3.  界面大小支持自适应屏幕大小，适配不同分辨率的电脑设备，支持全屏展示与分屏操作；
4.  数据可视化大屏的界面设计注重直观性与美观性，数字看板清晰醒目，可视化图表类型选择合理，配色协调，支持图表的交互操作（如鼠标悬停查看明细）；
5.  系统整体界面风格统一，字体、颜色、按钮样式保持一致，支持界面主题的简单切换（如浅色/深色）；
6.  操作界面提供清晰的提示信息与错误反馈，对必填字段、操作步骤、数据格式进行明确提示，对操作错误进行详细的原因说明。

**5.2 软件接口**

1.  数据可视化大屏的实时数据更新采用WebSocket协议，保证数据传输的实时性与稳定性；
2.  预留学校其他系统数据接口，支持与学校教务系统、科研系统、学生管理系统进行数据对接，实现数据的同步获取；
3.  预留Excel/WPS等办公软件的通用接口，保证数据导入导出的兼容性与流畅性；
4.  预留微服务数据接口，支持后续系统的微服务化改造与功能模块的独立扩展；
5.  预留手机端适配接口，支持后续开发手机端小程序/APP，实现数据的移动化查看；
6.  所有接口均进行标准化设计，提供详细的接口文档，包含接口地址、请求方式、参数说明、返回值说明，支持接口的权限控制与调用记录查询。
